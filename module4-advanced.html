Using the PMID37633276 example data, the advanced PrognosiX workflow keeps development and validation cohorts separate and covers univariable Cox and LASSO-based feature selection, survival-learner benchmarking, tuning, Kaplan–Meier risk groups, subgroup analysis, time-dependent AUC, calibration, nomograms, robustness checks, decision curves, SHAP, and deployment.

10.1 Important Notes

The optional development check runs only when the referenced local package path exists; GitHub and installed-package users can leave it skipped. Main settings are in OUTPUT_ROOT, the analysis version, outcome definitions, and the data-import section. Fix the prediction horizons and clinical decision thresholds in the analysis plan before examining validation results.

10.2 Step-by-step Workflow

The workflow is divided into short stages. Each note explains the purpose, key checks, and interpretation limits. Generated plots and tables appear directly below their code chunk.

10.2.1 About this chapter

Audience. Advanced users building and validating a clinical survival model with all diagnostic and explanatory tools.

Input. Reads data/PMID37633276_DIA_plasmaproomic.xlsx (sheet Table S1B) directly.

The chapter runs end to end as one session:

  1. CONFIG & Environment Setup
  2. Data Preparation (custom Excel data)
  3. Feature Selection (ONLY on training set)
  4. Algorithm Benchmarking & Hyperparameter Tuning
  5. Model Evaluation
  6. Robustness Analysis
  7. DCA & SHAP
  8. Save Final PrognosiX Object
  9. Deployment: Prediction for New Samples
  10. Final Report

                   "Lymphocytes%", "Monocytes%", "Neutrophilic granulocyte%", "Eosinophil%",

                   "Mean corpuscular hemoglobin concentration", "Red blood cell distribution width CV", 
                   "Red blood cell distribution width SD", "Platelet count", "Mean platelet volume", 
                   "PCT", "Platelet volume distribution width")]

inf <- raw_dis[, c("Case ID", "Sample type", "Plasma proteome ID", "Tissue proteome ID", 
                   "Gender", "Age at diagnosis", "Tobacco smoking history", "Drinking history", 
                   "Vital status", "Days to last followup", "Days until death", 
                   "Combined days to last followup or death", "Progressive-free survival_Status", 
                   "Progressive-free survival_Months", "Tumor location", "Tumor size (cm)", 
                   "T-category", "Lymph node involvement", "Distant metastasis", 
                   "TNM Stage", "Grade", "Morphology")]

# The group label lives in `inf` ONLY -- see the Module 1 chapter for why.
# Keeping it out of the feature matrix also frees its type: readable labels are
# fine, and they become the Table 1 column headers.
inf$group <- factor(ifelse(index, "Healthy Control", "Case"),
                    levels = c("Healthy Control", "Case"))
mat <- as.matrix(mat)
storage.mode(mat) <- "numeric"

rownames(mat) <- inf$`Case ID`
rownames(inf) <- inf$`Case ID`
mat <- as.data.frame(mat)
mat$age <- inf$`Age at diagnosis`
mat$sex <- inf$Gender

inf$time <- inf$`Combined days to last followup or death`
inf$event <- inf$`Vital status`
inf$event <- ifelse(inf$event == "Dead", 1, 0)

# Keep only disease samples (comparing against the label text, not a code --
# the group column is a factor, so `== 1` would silently match nothing)
inf <- inf[inf$group == "Case", ]
mat <- mat[rownames(inf), ]
mat$time <- inf$time
mat$status <- inf$event

stat_obj <- CreateStatObject(
  clean.data = mat,
  info.data = inf,
  group_col = "group",
  na.action = "allow"
)

# ---- 4.1 KM Curves ----
# IMPORTANT: The following KM curves and the cutoff derived from the training set
# are APPARENT (optimistic) performance. They are useful for internal exploration
# but MUST be re‑evaluated on an independent validation set before reporting.
pred_train <- best_lrn$predict(train_task)
cut_df <- as.data.frame(train_task$data())
cut_df$risk <- pred_train$crank

# Compute optimal cutoff using multiple methods.
# For publication, consider using 'maxstat' (Hothorn & Lausen, 2003) with
# bootstrap resampling to obtain a stable, data‑driven threshold.
# The 'p_optimize' method is also provided for historical consistency.
cut_res <- tryCatch({
  surv_cutpoint(cut_df, time = "time", event = "status", variables = "risk")
}, error = function(e) {
  warning("surv_cutpoint failed: ", e$message, ". Using median split.")
  list(cutpoint = data.frame(cutpoint = median(cut_df$risk, na.rm = TRUE)))
})
opt_cutoff <- cut_res$cutpoint$cutpoint
cat("Optimal cutoff (from surv_cutpoint):", round(opt_cutoff, 4), "\n")

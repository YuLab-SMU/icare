ICARE DEVELOPER GUIDE / 从模型到网页

把你的 icare 模型，
变成可交互的 Shiny 应用。

保存已经验证的模型，用 icare 构建输入与结果界面，再发布一个可分享的网址。这里提供三类应用的完整模板和从本地到云端的操作步骤。

STEP 01

先了解：网页在哪里运行

icare 把已训练的模型封装为 Shiny 应用。访问者在浏览器输入变量，R 服务执行预测，再把结果返回页面。准备模型、构建应用、托管应用是三个独立步骤。

训练与验证自己的数据 · icare
→
保存 RDS模型 · 预处理对象
→
app.R输入 · 预测 · 下载
→
Shiny 托管供浏览器在线访问

GitHub Pages 用于说明文档和应用入口；shinyapps.io 用于执行 R。把 app.R 放进 GitHub Pages，或把本地 Shiny 调用放进静态 Quarto 书籍，都不会自动获得在线 R 服务。GitHub Pages 文档 ↗

适用范围本教程从“已有训练完成的 icare 对象”开始。还没有模型时，先完成书籍中的 分类、分型或生存分析训练流程。应用仅加载模型进行预测。
STEP 02

准备环境，并固定版本

优先使用训练模型时的 R 环境。先确认模型能在本机预测，再准备发布工具。模板依据 icare 1.1.0 的固定提交核对，示例验证环境为 R 4.5.1；这里的版本是复现实例基线，不代表最新版本。

R
install.packages("rsconnect")
packageVersion("icare")
packageDescription("icare")$RemoteSha
sessionInfo()
新环境如何安装教程使用的 icare 版本？

先参考包的安装说明配置 R 和 Bioconductor。以下命令安装 icare 的直接依赖；应用使用的可选算法后端还需根据所选模板补齐。不要在训练完成后直接升级所有包。

R
install.packages(c("remotes", "BiocManager"))
BiocManager::install("ComplexHeatmap", ask = FALSE, update = FALSE)
remotes::install_github(
  "YuLab-SMU/icare@7ff676a556721affeb6da6c36b3bb60fc24ca468",
  dependencies = NA, upgrade = "never"
)

生存模块中的 mlr3proba、mlr3extralearners 等可能需要从其上游 GitHub 安装。请沿用训练时版本及来源，参考 mlr3proba、mlr3extralearners 和 icare 安装说明。安装命令不是所有系统的完整环境锁文件。

Bioconductor 的版本应与 R 匹配。可用 BiocManager::valid() 检查混用版本；不要把本例修复时使用的 S4Vectors 0.46.0 当成所有 R 版本都应安装的版本。

STEP 03

保存自己的模型与预处理对象

用途需要的对象应用构造函数
模块二 · 分类Train_Model，包含已拟合的 caret 模型ModelDeployment() → deploy_clinlab_app()
模块三 · 分型Subtyping，保存拟合过的方法New_Sub_Manager() → launch_sub_deploy_app()
模块四 · 生存风险PrognosiX，包含 best.model 和参考数据New_Prog_Manager() → launch_prog_deploy_app()

下载并解压模板包后，设置工作目录为 icare-shiny-starter。只需选择一种应用；下面的变量名是示例，请替换成训练会话中自己的对象名。

R
# 分类：model_obj 和 preproc 必须来自自己的训练流程
saveRDS(model_obj, "apps/classification/model.rds")
saveRDS(preproc, "apps/classification/preprocess.rds")
# 仅在确实没有外部预处理时，改用：
# saveRDS(NULL, "apps/classification/preprocess.rds")

# 分型：sub_obj 为训练完成的 Subtyping 对象
saveRDS(sub_obj, "apps/subtyping/model.rds")

# 生存：prog_obj 为训练完成的 PrognosiX 对象
saveRDS(prog_obj, "apps/survival/model.rds")
保存训练时的预处理，保留所有预测字段分类模型若使用标准化、变换或插补，必须复用训练阶段拟合的对象。不要对新输入重新拟合预处理，也不要将已经标准化的数据再次处理。性别等分类变量不能因不参与数值标准化而从输入字段中漏掉；类别值应与训练时一致。

RDS 对象可能包含训练记录。部署前检查数据使用权限；模型文件不要放在 www/ 或公开 GitHub 仓库。模板不会附带本项目的模型或训练数据。

STEP 04

准备目录和人工示例输入

保持相对路径。每个应用是一个独立目录，其 app.R 只读取当前目录中的模型。生存模板会在启动时执行示例预测，因此需要先生成并审查 www/example.csv。

目录结构
icare-shiny-starter/
├── apps/
│   ├── classification/
│   │   ├── app.R
│   │   ├── model.rds          # 添加自己的模型
│   │   ├── preprocess.rds     # 添加自己的预处理对象或 NULL
│   │   └── www/example.csv   # 生成并检查人工样例
│   ├── subtyping/            # app.R + model.rds + www/example.csv
│   └── survival/             # app.R + model.rds + www/example.csv
├── make_example.R
├── check_app.R
└── deploy.R

在模板根目录的终端运行以下命令。将 survival 换为 classification 或 subtyping 即可生成相应样例。

shell
Rscript make_example.R survival

脚本根据参考变量的分位数和类别生成三条人工组合。它们用于界面测试，不是验证集，也不一定符合实际变量间的关系；请检查单位、范围和类别。CSV 第一列为唯一的 SampleID，其余列名与模型预测字段完全一致。

输入方式：分类模板使用逐项手动输入，样例 CSV 用于复制数值，不提供批量上传；分型和生存模板支持手动输入与 CSV 批量上传。

STEP 05

用 icare 构建 app.R

以下为模板包中的完整 app.R。先选择一个展开查看；复制到对应应用目录后，修改标题、描述、变量单位和引用。不同训练算法可能需要额外的模型后端依赖。

模块二 · 分类应用app.R

适用于本教程的 caret 模型结构。输入字段从首个拟合模型中读取；请确认各模型的输入方案兼容。

apps/classification/app.R
library(shiny)
library(icare)
# Explicit imports also let rsconnect identify packages used by saved models.
library(caret)
library(C50)
library(glmnet)
library(kernlab)
library(klaR)
library(randomForest)
library(rpart)
library(MASS)
library(ipred)
library(bslib)
library(plotly)
library(jsonlite)
options(shiny.maxRequestSize = 10 * 1024^2)

model <- readRDS("model.rds")
preproc <- readRDS("preprocess.rds")
features <- setdiff(names(model@train.models[[1]]$trainingData), c(".outcome", model@group_col))
stopifnot(inherits(model, "Train_Model"), length(features) > 0)
deployment <- icare::ModelDeployment(
  model, preproc = preproc,
  class_labels = levels(model@split.data$training[[model@group_col]]),
  model_description = paste(
    "Describe your classification model and intended research use here.",
    "Enter the required predictors, select a model and click INITIATE ANALYSIS.",
    "The probability is a model output for research demonstration."
  )
)
# Include categorical predictors as well as numeric predictors.
# This template uses the caret training schema from the first fitted model.
deployment$preprocess_columns <- features
app <- icare::deploy_clinlab_app(deployment, title = "ICARE | Classification")
app

模块四 · 生存风险应用app.R

本模板声明 surv.ranger 及预后框架依赖。换成其他生存 learner 时，补充其算法后端。启动检查使用三条人工样例。

apps/survival/app.R
library(shiny)
library(icare)
library(shinydashboard)
library(DT)
library(mlr3)
library(mlr3proba)
library(mlr3extralearners)
# icare checks these optional packages dynamically when prediction is requested.
# Declare them explicitly so rsconnect includes them in the cloud bundle.
library(mlr3tuning)
library(mlr3tuningspaces)
library(paradox)
library(mlr3learners)
library(tidyverse)
library(data.table)
library(ranger)
library(survival)
options(shiny.maxRequestSize = 10 * 1024^2)

model <- readRDS("model.rds")
stopifnot(inherits(model, "PrognosiX"))
manager <- icare::New_Prog_Manager(model)
# Exercise the actual prediction path in the deployed runtime before serving UI.
local({
  example <- read.csv("www/example.csv", row.names = 1, check.names = FALSE)
  result <- manager$prog_predict(example, cutoff_method = "median", return_scores = TRUE)
  stopifnot(nrow(result) == nrow(example), all(is.finite(result$risk_score)),
            all(!is.na(result$risk_group)))
  message("ICARE survival startup prediction PASS: ", nrow(result),
          " artificial profiles; scores=", paste(result$risk_score, collapse = ","))
})
features <- model@best.model$features
icare::use_app_theme_grey()
icare::set_prog_app_text(
  title = "ICARE | Survival Risk",
  citation_text = "Replace with your study citation."
)
app <- icare::launch_prog_deploy_app(
  manager, title = "ICARE | Survival Risk",
  var_dict = data.frame(Feature = features, Description = gsub("_", " ", features),
                        Units = rep("Replace with the actual unit", length(features))),
  project_info = list(
    abstract = paste("Describe your fitted survival model and study here.",
                     "Enter the required predictors or upload a batch CSV to obtain risk scores and risk groups.",
                     "Example CSV profiles are artificial and are provided for interface testing."),
    citation = "Replace with your study citation."
  )
)
app

模板中的 var_dict 使用 Feature、Description、Units 三列。保留 Feature 的真实字段名，填写清楚描述及单位。分型和生存可通过 project_info 填写研究摘要及引用；生存主题与文字也可通过 use_app_theme_grey()、set_prog_app_text() 调整。

STEP 06

先验证预测，再测试网页

在模板根目录运行自动检查，再在 R 中启动应用。check_app.R 会调用真实 Shiny 服务端，检查预测、结果生成和下载。分类默认检查首个可选模型，分型默认检查 NMF；发布其他方法前应逐一验证。

shell
Rscript check_app.R survival
# 分型可指定实际已拟合的方法：
Rscript check_app.R subtyping nmf
Rscript check_app.R subtyping lpa
Rscript check_app.R subtyping kmeans
# 分类：
Rscript check_app.R classification
R
# 在 R 控制台中，每次启动一个应用
shiny::runApp("apps/survival")
# shiny::runApp("apps/classification")
# shiny::runApp("apps/subtyping")
  • 输入一条人工样例，点击计算，确认结果区没有错误。
  • 分型、生存再上传 CSV，核对样本 ID、行数与下载内容。
  • 确认单位、分类水平和缺失值行为与训练流程一致。
  • 生存测试 median、tertile、custom；自定义阈值须为有序且不重复的数值。
  • 重新启动 R 后再运行，排除对全局变量或未声明包的依赖。

网页能显示不等于预测可用。自动检查也不代替浏览器上的点击、上传和下载复核。生存风险分数是模型输出，不应直接解释为某个时点的事件概率。

STEP 07

检查部署依赖，避免云端缺包

rsconnect 会扫描应用代码中的包调用，并生成依赖清单。保存在 RDS 中的模型后端、以及包内部动态检查的可选依赖，可能不会仅凭 library(icare) 被完整发现。依赖发现说明 ↗

R
deps <- rsconnect::appDependencies(
  appDir = "apps/survival",
  appFiles = c("app.R", "model.rds", "www/example.csv"),
  appMode = "shiny"
)
deps[, c("Package", "Version", "Source")]
required <- c("mlr3", "mlr3proba", "mlr3tuning", "mlr3tuningspaces",
  "mlr3learners", "mlr3extralearners", "tidyverse", "paradox",
  "data.table", "survival", "ranger")
stopifnot(all(required %in% deps$Package))
本项目实际遇到的错误第四模块最初可以打开，但计算时依次报告缺少 mlr3tuning、mlr3tuningspaces、mlr3learners、tidyverse。完整模板已显式声明这些依赖，并加入启动预测检查。部署脚本还会检查清单中是否包含预后框架所需包。

记录模型所用的 R、icare 和算法包版本及来源。若使用 renv.lock，要在验证后更新锁文件并保持其与本地库一致；避免把旧锁文件与新的模型混用。共享模板没有提供通用于所有模型的锁文件。

STEP 08

发布到自己的 shinyapps.io 账户

  1. 注册 shinyapps.io，记下自己的 Account name。
  2. 在账户的 Tokens 页面取得配置命令，仅在本机 R 控制台运行。不要把真实 token/secret 放进 app.R、GitHub、截图或教程。
  3. 确认账户已绑定，然后从模板根目录发布所选应用。
R
# 先在本机 R 控制台运行账户页面提供的 setAccountInfo(...) 命令。
# 下面只显示已绑定账户，不包含令牌：
rsconnect::accounts()
shell
# 终端：替换成自己的账户名和应用名
Rscript deploy.R survival YOUR_ACCOUNT my-survival-app

发布脚本仅上传 app.R、模型、人工示例，以及分类所需的预处理文件，并请求公开访问。请使用自己的账户与新的应用名；不要照抄本项目的 icare01。首次发布需要云端安装 R 包，耗时依赖包数量和服务器状态。

发布成功后打开工具返回的真实 URL，用未登录的浏览器会话测试：手动预测、支持的批量上传、结果下载。休眠后的首次访问可能需要等待启动。额度与可用资源以自己的账户套餐为准。Posit 发布指南 ↗

R
# 在 R 控制台读取自己的应用日志
rsconnect::showLogs(
  appName = "my-survival-app", account = "YOUR_ACCOUNT",
  server = "shinyapps.io", entries = 100, streaming = FALSE
)

生存模板启动成功时，日志应包含 ICARE survival startup prediction PASS。这确认服务器执行过人工样例预测；仍需完成网页实际操作复核。

STEP 09

把入口放进 GitHub 或 Quarto

Shiny 发布完成后，给说明页添加普通链接最直接。下面域名是占位示例，必须替换成自己的真实应用 URL。

html
<a href="https://YOUR_ACCOUNT.shinyapps.io/my-survival-app/"
   target="_blank" rel="noopener">打开我的 Shiny 应用</a>

如需要在页面中展示应用，也可以嵌入 iframe，并保留上面的独立打开链接作为备用入口。嵌入显示受浏览器和托管服务策略影响。

html
<iframe
  src="https://YOUR_ACCOUNT.shinyapps.io/my-survival-app/"
  title="我的生存风险应用"
  style="width:100%;height:900px;border:0">
</iframe>

若使用 Quarto book，把静态入口放在项目源目录，例如 review-apps/，并将资源规则合并进已有的 _quarto.yml。不要只手动上传输出目录，否则下次渲染可能丢失页面。

yaml
project:
  type: book
  resources:
    - review-apps/**

在章节中加入 [打开应用](review-apps/index.html)，再通过自己的 Quarto 发布流程更新网站。GitHub Pages 仓库的设置、发布分支或 Actions 工作流需要与自己的站点一致。Quarto resources 选项 ↗

STEP 10

按错误出现的位置排查

现象先检查什么
本地正常，云端点击计算报错读取 showLogs；核对动态依赖、模型后端、包版本及依赖清单。HTTP 200 只说明页面响应。
找不到 model.rds / example.csv检查应用目录、相对路径、文件名大小写及 appFiles 上传列表。云端不能读取电脑上的绝对路径。
缺少变量、类别不匹配、预测值异常对照真实训练字段与 factor levels；确认原始单位、列名、预处理对象，并排除重复标准化。
CSV 上传失败或行数不对第一列使用唯一且非空的样本 ID；其余列名与模型一致。检查字符编码、空值与文件大小。
Bioconductor 安装或编译失败运行 BiocManager::valid()，核对 R 与 Bioconductor 版本、软件仓库、系统依赖和网络。
应用启动即退出检查启动预测日志；依赖缺失、样例与模型字段不一致或模型对象不完整会使检查失败。
iframe 空白或断开先直接打开 Shiny URL；区分嵌入策略、休眠唤醒、服务错误及账户资源限制。
换模型后仍得到旧结果核对部署账户、应用名和本地 RDS 文件；重新部署并关闭旧会话后再测试。

向协作者报告问题时，提供 R/icare 版本、对象类型、发生错误的操作和脱敏日志。不要附账户令牌或真实患者输入。

发布前的最后一步

让一位没有本地 R 环境的同事，通过公开链接完成一次预测与结果下载。确认后，再把入口用于论文或项目说明。
